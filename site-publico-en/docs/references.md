# References

ZirconTrace doesn't invent new stages: each one is anchored on an already-recognized industry standard. These are the references we use.

| Framework | Where we use it | Source |
|---|---|---|
| **AWS Well-Architected Framework** | Read (current-state review) and Architect (design checklist), across the 6 pillars: Operational Excellence, Security, Reliability, Performance Efficiency, Cost Optimization, Sustainability. | [aws.amazon.com/architecture/well-architected](https://aws.amazon.com/architecture/well-architected/) |
| **AWS Cloud Adoption Framework (CAF)** | Read, to evaluate gaps by perspective: Business, People, Governance, Platform, Security, Operations. | [aws.amazon.com/cloud-adoption-framework](https://aws.amazon.com/cloud-adoption-framework/) |
| **FinOps Framework** | Cross-cutting across all 5 stages, mapped to its 3 real phases: Inform (Architect), Optimize (Craft), Operate (Evolve). | [finops.org/framework](https://www.finops.org/framework/) |
| **Working Backwards (PR/FAQ)** | Target, to start from the business outcome before the technical solution. | Amazon's methodology, documented in the book *Working Backwards* (Bryar & Carr, 2021). |
| **Double Diamond (Design Thinking)** | Target, as the discovery narrative: first we diverge to fully explore the problem, then we converge on prioritized use cases. | [designcouncil.org.uk/resources/the-double-diamond](https://www.designcouncil.org.uk/resources/the-double-diamond/) |
| **CRISP-DM** | Read, as a process reference for data and machine learning projects. | [datascience-pm.com/crisp-dm-2](https://www.datascience-pm.com/crisp-dm-2/) |
